Key Challenges & Solutions
Challenge
Korean prompts contain politeness markers and discourse fillers ("if it's okay", "when you have time") that inflate token count and confuse naive task extraction.
Solution
Separated translation (Role 1) from task analysis (Role 2). Dedicated TaskCandidateExtractor removes meta-expressions before classification, preserving only executable intent.
Challenge
Users describe multi-step tasks out of execution order ("fix X after checking Y"), making sentence order unreliable as a proxy for task dependencies.
Solution
Built FLOWS_TO type transition table encoding which task types naturally precede others. Combined with Kahn's algorithm for topological sort — deterministic, order-independent execution.

DeToks addresses a real developer pain point: Korean-language prompts are verbose and expensive to run through paid LLM APIs. By moving optimization upstream — into structured task decomposition and context compression — it reduces cost without sacrificing execution quality. The CLI-first architecture and multi-adapter support (Claude, Codex, Gemini) make it directly applicable to enterprise developer tooling workflows.

  • Created the FLOWS_TO dependency transition table defining natural execution order between task types; integrated Kahn's algorithm for topological sort
  • Built DAGValidator to catch unknown dependencies, cycles, and disconnected nodes before execution
  • Implemented TaskCandidateExtractor to strip polite prefixes, discourse fillers, and meta-instructions from normalized input
  • Added 50+ regression tests on compound requests; validated against 106-sample corpus and 1,000+ individual prompts
Core Features
  • Prompt Compiler: local LLM (supergemma-4-e4b) translates Korean → English with identifier masking, achieving ~30% token reduction and 99%+ accuracy
  • 8-type task classifier with FLOWS_TO dependency table and DAG validation — deterministic, non-probabilistic task ordering
  • Dual-tier session context compression: keeps 3 recent tasks in full, compresses older tasks dynamically per adapter budget (85K–485K tokens)
  • Multi-adapter CLI wrapper with REPL commands, ASCII spinners, and error-to-Korean summary conversion

Key Challenges & Solutions
Challenge
Midnight-crossing shifts (e.g., 20:00–05:00) produce negative duration when naively subtracted, breaking the entire salary calculation pipeline.
Solution
If end.isBefore(start), add Duration(days: 1) to end DateTime. Handles all overnight shifts correctly, including break deductions across midnight.
Challenge
Night-shift premium (22:00–06:00 at 1.5x) may partially overlap a shift — calculating the exact intersection requires two-dimensional time math spanning two calendar dates.
Solution
Explicit overlap logic: max(shiftStart, windowStart) → min(shiftEnd, windowEnd). Precise to the minute; handles partial, full, and no-overlap cases without branching per scenario.

Built from direct HR and hotel industry experience — the problem is real, the edge cases are real, and no existing app handles them correctly. WorkWage demonstrates the ability to translate domain expertise into a production-ready mobile product, from algorithm design through monetization strategy and Play Store launch.
